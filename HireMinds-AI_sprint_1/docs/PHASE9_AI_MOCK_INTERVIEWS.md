# Phase 9 — AI Mock Interviews

> **Status:** Implemented (backend only; no frontend in this phase)
>
> **Important Disclaimer:** AI-generated evaluations and rubric scores are
> practice-oriented feedback tools for interview preparation. They are **not** an
> objective measurement of a person's capability, do **not** reliably predict
> real-world on-the-job performance, and must **never** be used for automated hiring
> or rejection decisions.

---

## 1. Purpose

Phase 9 implements text-based AI mock technical interviews in HireMinds AI powered
by Google Gemini (and DeepSeek as a supported fallback).

Key capabilities:
- **Role-grounded questions:** Questions are generated dynamically from the target
  job's requirements and the candidate's verified skills.
- **One-at-a-time interactive delivery:** Questions are presented sequentially. Only
  one question is active and awaiting an answer at any time.
- **Contextual follow-up generation:** If an answer invites deeper exploration of an
  architecture, trade-off, tool, or edge case, the system generates contextual
  follow-up questions linked to the parent question.
- **Predefined 4-dimension rubric scoring:** Each answer is evaluated across Technical
  Correctness, Relevance, Clarity, and Reasoning on a 1.0–5.0 scale, producing an
  explainable 0–100 overall score and constructive feedback.
- **Session-level insights:** Once the interview reaches its target question count or
  is manually completed, the system generates overall strengths, weaknesses,
  actionable improvement suggestions, and recommended topics for further study.
- **Resuming and reviewing:** Candidates can resume active in-progress interviews or
  review past completed interview evaluations.
- **Total isolation from ATS scoring:** Interview sessions, questions, answers, and
  evaluations are stored in dedicated tables and never influence ATS scores or match
  results.

## 2. System Architecture & Lifecycle

```
[Candidate] ---> POST /api/v1/interviews/start
                      │
                      ├──> Active session exists? ───> Resume session & return current pending question
                      │
                      └──> Create InterviewSession (in_progress)
                           └──> Gemini generates Question 1 (order_index=1, is_follow_up=False)

[Candidate] ---> GET /api/v1/interviews/{id}/current-question
                      │
                      └──> Returns active pending question

[Candidate] ---> POST /api/v1/interviews/{id}/questions/{q_id}/answer
                      │
                      ├──> Gemini evaluates answer across 4-dimension rubric (1.0 - 5.0)
                      ├──> Stores InterviewAnswer (technical_correctness, relevance, clarity, reasoning, score)
                      │
                      ├──> Target questions reached? (or max questions reached)
                      │     ├──> YES: Finalize session (status=completed, generate InterviewEvaluation)
                      │     └──> NO:
                      │           ├──> Answer warrants follow-up & follow_ups < max_follow_ups?
                      │           │     ├──> YES: Generate contextual follow-up question (parent_question_id = q_id)
                      │           │     └──> NO: Generate new topic question from required job skills
                      │           └──> Store InterviewQuestion (order_index = N + 1)
                      └──> Return result with next question or completion notice
```

## 3. Predefined Rubric Scoring

Every answer is evaluated across four predefined rubric dimensions on a **1.0 to 5.0** scale:

| Dimension | Weight / Scale | Description |
| :--- | :--- | :--- |
| **Technical Correctness** | 1.0 – 5.0 | Factual and conceptual accuracy of technologies, algorithms, syntax, and principles. |
| **Relevance** | 1.0 – 5.0 | How directly and completely the candidate addressed all aspects of the prompt. |
| **Clarity** | 1.0 – 5.0 | Structural coherence, conciseness, articulation, and professional technical communication. |
| **Reasoning** | 1.0 – 5.0 | Justification of choices, analysis of trade-offs, edge cases identified, and critical thinking depth. |

### Derived Answer Score Formula:
$$\text{Overall Answer Score} = \left(\frac{\text{Correctness} + \text{Relevance} + \text{Clarity} + \text{Reasoning}}{20.0}\right) \times 100$$

### Session-Level Evaluation:
When a session concludes, the session averages are calculated deterministically across all submitted answers:
- `overall_score`: Mean of all answer overall scores (0–100).
- `technical_correctness`: Mean correctness (1.0–5.0).
- `relevance`: Mean relevance (1.0–5.0).
- `clarity`: Mean clarity (1.0–5.0).
- `reasoning`: Mean reasoning (1.0–5.0).

Qualitative feedback generated by LLM:
- **Overall Summary:** A comprehensive paragraph summarizing candidate depth and style.
- **Strengths:** 2 to 5 specific demonstrated technical or problem-solving strengths.
- **Weaknesses:** 2 to 5 specific gaps, misconceptions, or areas needing development.
- **Improvement Suggestions:** Actionable interview preparation tips.
- **Recommended Topics:** Specific technical domains, architectures, or tools for study.

## 4. API Reference

Base path: `/api/v1/interviews`

| Method | Endpoint | Role | Purpose |
| :--- | :--- | :--- | :--- |
| `POST` | `/start` | Candidate | Start a new mock interview or resume an in-progress session |
| `GET` | `/` | Candidate / Recruiter | List candidate interviews (recruiters view sessions for their jobs) |
| `GET` | `/{session_id}` | Owner / Recruiter / Admin | View full session transcript (questions, answers, evaluation) |
| `GET` | `/{session_id}/current-question` | Candidate | Retrieve the currently active pending question |
| `POST` | `/{session_id}/questions/{question_id}/answer` | Candidate | Submit an answer, receive rubric score and next question |
| `POST` | `/{session_id}/complete` | Candidate | Manually finalize in-progress interview and generate feedback |
| `GET` | `/{session_id}/evaluation` | Owner / Recruiter / Admin | Retrieve post-interview evaluation report and study recommendations |

### Error Status Codes:
- `400 Bad Request`: Submitting an answer after interview is already completed.
- `403 Forbidden`: Candidate attempting to access or answer another user's interview, or recruiter attempting to view interviews for jobs they do not own.
- `404 Not Found`: Session, job, question, or evaluation not found.
- `409 Conflict`: Attempting to submit a second answer to a question that has already been answered.
- `502 Bad Gateway`: Upstream LLM provider returned invalid formatting or API failure.
- `503 Service Unavailable`: LLM provider is unconfigured (e.g. missing `GEMINI_API_KEY`).
- `504 Gateway Timeout`: Upstream LLM provider request timed out.

## 5. Security, Resilience & Ethical Safeguards

1. **Strict Separation from ATS Scoring**:
   - Interview sessions, questions, answers, and evaluations live in separate tables (`interview_sessions`, `interview_questions`, `interview_answers`, `interview_evaluations`).
   - The ATS engine (`ats_service.py`) and matching database tables (`match_results`) never read or modify interview data.
2. **Deterministic Fallback**:
   - If the LLM provider experiences an unexpected outage or rate limit during session completion, the service automatically falls back to deterministic summary generation (`generation_status="fallback"`). Rubric scores are derived mathematically from existing answers, so a candidate never loses their completed interview.
3. **Strict Validation of Model Output**:
   - All LLM outputs are treated as untrusted JSON input. Prompt lengths, difficulty bounds, score bounds (1.0–5.0), and non-empty responses are strictly enforced before persistence.
4. **Non-predictive Performance Notice**:
   - Every evaluation persists an explicit disclaimer:
     > *"This AI-generated evaluation is provided for interview practice and preparation guidance only. It is not an objective hiring decision, does not guarantee or predict actual employment outcomes, and must be reviewed alongside comprehensive human evaluation."*
